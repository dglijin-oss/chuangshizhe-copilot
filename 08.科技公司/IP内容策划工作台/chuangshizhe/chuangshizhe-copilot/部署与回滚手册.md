## 调试记录（按时间顺序）

### 1. Docker 构建失败：Prisma generate 找不到输出路径
- **现象**: `Module not found: Can't resolve '../generated/prisma'`
- **根因**: `prisma.config.ts` 中的 `datasource.url` 读取 `DATABASE_URL`，Docker 构建时该变量不存在，导致 `prisma generate` 静默失败；另外曾尝试绝对路径 `/app/src/generated/prisma`，在 Windows 上被解析为 `..\..\..\app\src\generated\prisma`
- **修复**: 
  - 移除 `prisma.config.ts` 中的 `datasource` 配置，不依赖环境变量
  - 恢复 schema 中使用相对路径 `../src/generated/prisma`

### 2. Docker 构建失败：Zod 环境变量验证
- **现象**: 编译通过但 `Collecting page data` 阶段报错 `ZodError: DATABASE_URL must be valid URL`
- **根因**: Next.js 构建时收集 page data 会执行 API 路由的 side-effects，`env.ts` 在模块加载时同步运行 Zod 校验
- **修复**:
  - `env.ts` 中加 `SKIP_ENV_VALIDATION` 开关，设置时跳过验证
  - `Dockerfile` 的 builder 和 runner 阶段均设置 `ENV SKIP_ENV_VALIDATION=1`

### 3. 容器启动失败：无法连接数据库
- **现象**: `Invalid prisma.user.findUnique() invocation: Can't reach database server`
- **根因**: 数据库在宿主机本地，Docker 容器默认 bridge 网络无法访问宿主机的 127.0.0.1
- **修复**: 容器使用 `--network host` 模式，容器内的 127.0.0.1 即宿主机

### 4. 登录成功但页面一直跳回首页
- **现象**: 输入账号密码登录后刷新又回到未登录状态
- **根因**: `NODE_ENV=production` 导致 cookie 设置了 `secure` 标志，浏览器在 HTTP（非 HTTPS）下拒绝存储该 cookie
- **修复**: 将 `src/app/api/auth/login/route.ts` 和 `register/route.ts` 中的 `secure: process.env.NODE_ENV === "production"` 改为 `secure: false`（后续配置 HTTPS 后再改回）

### 5. 部署后 IP 数据"丢失"
- **现象**: 本地开发时创建的 IP 人设，服务器部署后看不到
- **排查**: `.env` 中 `DATABASE_URL` 指向 `111.228.45.216:5432`，本地和服务器共用同一数据库
- **结论**: 数据并未丢失，是之前 cookie 问题导致登录的不是同一个会话

### 6. IP 编辑页 UX 优化
- 添加底部固定（sticky）保存栏，页面滚动时始终可见
- 移除顶部和底部的「删除此 IP」按钮，防止误删

## 当前部署流程

```bash
# 1. 提交代码
git add . && git commit -m "修改说明" && git push

# 2. 一键部署
bash deploy.sh
```

每次部署自动打版本标签（如 `v-a6a4d7a-05201500`），旧镜像保留在服务器上。

## 回滚

### 交互式回滚（推荐）

```bash
bash rollback.sh
```

会列出所有可用版本及构建时间，例如：

```
序号  版本标签                      构建时间
----  --------------------------    -------------------
1     v-4ae1615-05201458            2026-05-20 14:58:00 +0800 CST
2     v-e9cd57e-05201430            2026-05-20 14:30:00 +0800 CST
3     v-7543074-05201400            2026-05-20 14:00:00 +0800 CST
```

输入序号选择回滚目标，或直接回车回滚到上一个版本。

### 指定版本回滚

```bash
bash rollback.sh v-4ae1615-05201458
```
